agentic ai · open source

Invio: a graph-based accounts payable agent

An agent that watches an inbox, reads invoices and routes them. It runs as a 22-node ADK graph: 3 LLM agents and 19 deterministic nodes, so the model is only called where judgment is needed.

Invoice email → Model Armor screen → Screening agent → Extraction agent → Rules · PO match · duplicates → Approve and post Human approval Rejection email
LLM agent Deterministic code Human decision
Challenge
Invoices arrive as unstructured PDFs, and letting a model approve payments on its own is a risk nobody should accept.
Approach
The model only proposes structured data. Rules, duplicate detection and PO matching decide. Invoices over $4,000 or with flags wait for a person. Model Armor quarantines prompt-injection PDFs before any model reads them, and Gemini models are routed per document complexity.
Outcome
A predictable, auditable and cheaper flow, built around the principle that the AI reads; rules and people decide.

How I Build

01

The AI proposes. Code and people decide.

Use models for judgment, and deterministic nodes for everything that must be predictable and auditable.

02

Design the failure path first.

Assume every consumer will fail. Retries, dead-letter queues and a way to replay come before the happy path.

03

Make the right way the easy way.

Ship secure defaults as a library, not a wiki page. Teams adopt what saves them time.

04

Draw boundaries before writing services.

Clear service boundaries keep a 100+ service ecosystem coherent instead of a distributed monolith.

05

Use the cheapest model that does the job.

Route by document complexity. Bigger models earn their cost only where the task needs them.
